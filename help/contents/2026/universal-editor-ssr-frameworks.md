# 具有通用编辑器和现代SSR框架的快速、可编辑站点

现代Web团队希望能够自由使用Headless和现代JavaScript框架，而无需牺牲对营销人员的上下文编辑。 在此会话中，我们展示了Adobe Experience Manager通用编辑器和现代服务器端渲染(SSR)框架（如React和Next.js样式设置）如何交付快速的搜索引擎优化(SEO)站点，作者仍可以对这些站点进行可视化编辑。 我们解释了如何将通用编辑器引入基于框架的应用程序中，SSR如何影响性能和Core Web Vitals，以及如何构建组件以使作者可以在不破坏前端的情况下安全更新体验。 如果您计划或更新Adobe Experience Manager (AEM)或Edge Delivery Services (EDS)项目，则此网络研讨会提供了一个可立即使用的实用蓝图。

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## 关键要点

* **何时使用标准EDS站点与自定义SSR框架**
我们理解为什么标准Adobe Experience Manager Edge Delivery Services (EDS)站点是大多数项目的最佳默认站点，以及为什么有必要将通用编辑器分层到现有应用程序（如商店或门户）上而不是进行重建。

* **Universal Editor如何插入到EDS和现有框架中**
我们了解了Universal Editor如何适应典型的AEM EDS设置，以及在将其连接到生产中已有的React或Next.js样式的SSR应用程序时，相同概念如何适用。

* **SSR，它计算平衡EDS默认值与性能和SEO需求**
我们已经了解了何时可以依赖EDS默认设置以及何时真正需要针对特定体验的自定义服务器端渲染(SSR)，包括对于产品详细信息或登陆页面等高价值页面对SEO和Core Web Vitals的影响。

* **未破坏开发人员和营销人员应用程序模式的创作**
我们发现了组件和内容模型模式，这些模式允许开发人员保留干净的可维护代码库，同时为作者提供安全的上下文编辑功能，无论是在标准EDS站点上还是与现有框架集成。
